# תתבוס — קופה למזנון הישיבה

קופה עם ארנק טעון מראש לכל בחור. עובדת גם בלי אינטרנט ומסתנכרנת בין כמה מכשירים (קופה ראשית, טאבלט, מחשב נייד).

## מה יש בגרסה הזאת

| מסך | מה עושים בו |
|---|---|
| 🛒 **קופה** | לוחצים על מוצר (תמונה או אימוג׳י) או סורקים ברקוד. בוחרים בחור לפי כרטיס או שם. משלמים מהארנק או במזומן, עם חישוב עודף. אפשר לתת אחוזי הנחה, ויש מחיר מוכרים. מתוך "מכירות אחרונות" מבטלים מכירה. |
| 👛 **ארנקים** | טעינה במזומן, בהעברה/ביט או דרך המשרד. רואים היסטוריה של כל בחור, שולחים דו״ח להורים בוואטסאפ, מסננים יתרה נמוכה ומייצאים לאקסל. |
| 📦 **מלאי** | מוצרים עם מחיר, מחיר מוכרים, עלות, ברקוד, קטגוריה, ספק, מינימום ומלאי רצוי. מתעדים קבלת סחורה ועושים ספירת מלאי. |
| 🚚 **הזמנות** | ספקים. המערכת מציעה הזמנה לפי מה שירד מתחת למינימום, שולחים לספק בוואטסאפ, ובסימון "התקבלה" המלאי מתעדכן. |
| 📊 **דוחות** | יומי, שבועי, חודשי ושנתי: הכנסות, מזומן מול ארנק, רווח גולמי, הכי נמכרים, הולכים פחות, לפי מוכר, לפי קטגוריה וביטולים. ייצוא לאקסל והדפסה. |
| 💰 **ספירה** | ספירת קופה לפי שטרות ומטבעות, בכל שעה. מראה כמה צפוי במגירה, את ההפרש ואת הסכום שנשאר לפתיחה. |
| ⚙️ **הגדרות** | מוכרים עם קוד אישי והרשאות: ביטול מכירות, טעינה, הנחות ודוחות. שם המכשיר, גיבוי ושחזור. |

**מי עשה מה:** כל מכירה, ביטול, טעינה וספירה נשמרים עם המוכר שהיה מחובר ועם המכשיר.
**נעילה אוטומטית:** אחרי 10 דקות בלי פעילות.
**סורק ברקודים:** כל סורק USB או Bluetooth שעובד כמקלדת. אין צורך בהגדרה. אפשר לסרוק מוצר וגם כרטיס של בחור.
**סריקה במצלמה:** בכפתור 📷, ב-Chrome באנדרואיד.

## התקנה (דרך הממשקים באתר, בלי מחשב פיתוח)

### 1. Supabase
1. צור פרויקט חדש ב-supabase.com.
2. **SQL Editor** → הדבק והרץ את `supabase/schema.sql`, ואחריו את `supabase/members.sql`.
3. **Authentication → Sign In / Providers → Email**: מכבים את **Confirm email** ושומרים. כך ההרשמה באפליקציה עובדת מיד, בלי מייל אישור, שנטפרי עלול לחסום.
4. **Project Settings → API Keys**: העתק את ה-`Project URL` ואת ה-`publishable key`.

**איך עובדת הכניסה:** במכשיר הראשון בוחרים **"פעם ראשונה — רישום המזנון"** וקובעים מייל וסיסמה. בכל מכשיר נוסף בוחרים **"יש לי כבר חשבון"** ונכנסים עם אותם פרטים.
המייל הראשון שנרשם הופך לחשבון המזנון. מי שנרשם אחריו עם מייל אחר נחסם ולא רואה שום נתון.

### 2. GitHub
צור ריפו חדש (למשל `tatbus`) והעלה את כל הקבצים מהתיקייה, כולל `src`, `public` ו-`supabase`.

### 3. Vercel
1. New Project → בחר את הריפו. Vercel מזהה Vite לבד.
2. ב-**Environment Variables** הוסף:
   - `VITE_SUPABASE_URL` = ה-Project URL
   - `VITE_SUPABASE_ANON_KEY` = ה-anon key
3. Deploy.

### 4. נטפרי
צריך לבקש פתיחה של:
- כתובת ה-Vercel של האפליקציה
- `xxxx.supabase.co` (הכתובת של הפרויקט שלך), כולל WebSocket לזמן אמת

### 5. חיבור מכשיר
פותחים את הכתובת בכל מכשיר, נכנסים פעם אחת עם המייל והסיסמה של המזנון, ומוסיפים למסך הבית (התקנת אפליקציה).
- כניסה ראשונה: מוכר **"מנהל"** עם קוד **1234**. כדאי לשנות את הקוד מיד בהגדרות.
- בהגדרות → "המכשיר הזה" נותנים לכל מכשיר שם, למשל "קופה ראשית" או "טאבלט חדר אוכל". השם מופיע בדוחות ובספירת הקופה.

> **בלי Supabase:** אם לא מגדירים את משתני הסביבה, האפליקציה עובדת במצב מקומי על מכשיר אחד. זה טוב לניסיון. בהגדרות יש כפתור "טען נתוני דוגמה".

## איך עובדת עבודה בלי אינטרנט

- כל פעולה נשמרת קודם במכשיר (IndexedDB) ונכנסת לתור. כשיש רשת, התור נשלח לשרת ומושכים שינויים ממכשירים אחרים. זה קורה מיד, וגם כל 20 שניות ובזמן אמת.
- **יתרות ומלאי לא נשמרים כמספר.** הם מחושבים מסכום התנועות: טעינות, קניות, ביטולים, קבלות וספירות. לכן שתי קופות שמוכרות במקביל בלי אינטרנט לא דורסות זו את זו, וכשהן מתחברות הכל מסתדר.
- בעריכה של אותו מוצר או בחור משני מכשירים, העריכה האחרונה נשארת.
- **מגבלה אחת:** אם שני מכשירים בלי אינטרנט מוכרים לאותו בחור באותו זמן, כל מכשיר רואה רק את המכירות שלו. במקרה כזה הבחור יכול לרדת קצת למינוס. כשהמכשירים מתחברים היתרה מתעדכנת לסכום הנכון.
- הנורה למעלה: 🟢 מסונכרן · 🟡 לא מקוון (המספר בסוגריים = כמה פעולות מחכות) · 🔴 שגיאה (לחיצה מנסה שוב).

## 💳 אשראי דרך נדרים פלוס + 🧾 קליטת חשבוניות (גרסה 0.2)

### מה נוסף
- **בקופה:** כפתור **💳 אשראי**, שפותח את טופס התשלום של נדרים פלוס בתוך הקופה. מקלידים את הכרטיס, בלי מכשיר.
- **בקופה:** כפתור **🏧 שולם במסוף**. חובה להזין מספר אישור ו-4 ספרות אחרונות, וזה מגיע עם השוואה מול סגירת היום במסוף, במסך הספירה.
- **בארנקים:** טעינה באשראי, טעינה במסוף, ו-**🔗 קישור טעינה להורים** שנשלח בוואטסאפ ובו ההורים משלמים לבד.
- **במלאי:** **🧾 קליטת חשבונית**. מצלמים או מעלים חשבונית או תעודת משלוח, אפשר כמה עמודים, והמערכת קוראת את הפריטים. במסך אישור בודקים ומתקנים, ורק אחרי האישור המלאי והעלויות מתעדכנים.
- **במוצר:** כפתור **📷 צלם** שמצלם ישר מהמצלמה, ליד **🖼 גלריה**.

### איך מוודאים שתשלום באשראי אמיתי
כל תשלום נרשם בשרת לפני החיוב. נדרים פלוס שולחים אישור ישירות לשרת שלנו (פונקציה בשם `nedarim`), והשרת בודק שלושה דברים: שהאישור הגיע מכתובת של נדרים, שהסכום תואם, ושהתשלום לא נוצל כבר. רק אז נרשמת הטעינה.
תשלום שלא אומת מופיע בדוחות תחת "⚠ תשלומי אשראי לבדיקה". מנהל יכול לבדוק אותו בנדרים ולאשר ידנית.

### התקנה ב-Supabase (פעם אחת)

**1. פונקציה `nedarim`:**
Edge Functions ← **Deploy a new function** ← **Via Editor** ← שם: `nedarim` ← מדביקים את התוכן של `supabase/functions/nedarim/index.ts` ← **Deploy**.
אחר כך בפונקציה: **Details** ← מכבים את **Verify JWT** ← **Save**. זה חובה, כי נדרים פלוס וההורים פונים אליה בלי התחברות.

**2. פונקציה `invoice-scan`:**
אותו דבר, עם התוכן של `supabase/functions/invoice-scan/index.ts`. כאן **משאירים** את Verify JWT דלוק.

**3. סודות:** Edge Functions ← **Secrets** ← Add:
- `ANTHROPIC_API_KEY`: מפתח של Claude API מ-console.anthropic.com. בלעדיו אין קריאת חשבוניות.
- `NEDARIM_API_PASSWORD` (לא חובה): מפתח ה-ApiPassword של נדרים (`npk_…`). נשמר רק בשרת ולא באפליקציה, ומשמש לאימות כפול של תשלומים.

**4. בתתבוס:** ⚙️ הגדרות ← **💳 תשלום באשראי — נדרים פלוס** ← מספר מוסד + טקסט אימות (ApiValid) ← שמור.

**5. נטפרי:** לבקש פתיחה גם ל-`matara.pro` (טופס התשלום).

**6. הרשאות:** למוכרים קיימים צריך להפעיל ידנית את "מותר לרשום שולם במסוף", בהגדרות ← מוכרים.

## גרסה 0.4
- **🖨 מחירון** (מסך מלאי): אפשר לסדר לפי קטגוריות או לפי א-ב, ב-1, 2 או 3 טורים, עם תמונות ועם אותיות גדולות לתליה. בראש הדף ובתחתיתו מודפס תאריך עדכון, ולצידו המשפט "ייתכנו שינויים מעת לעת — ולכן המחיר בקופה הוא הקובע". שם המזנון נלקח מ⚙️ הגדרות ← פרטי המזנון.
- **📧 הזמנה במייל:** לכל ספק אפשר להוסיף כתובת מייל. בהזמנה בוחרים **מייל**, שפותח טיוטה מוכנה בתוכנת המייל, או **Gmail**, שפותח טיוטה ב-Gmail בדפדפן. הנוסח כולל את הפריטים והכמויות, ובסופו איש הקשר, הטלפון והכתובת מההגדרות.
- **📟 אשראי במסופון:** זמין תמיד, גם בלי חיבור לנדרים אונליין. המסך מציג את הסכום לתשלום, סולקים במסופון, ומקלידים את מספר האישור או העסקה ואת הטלפון של הקונה. 4 הספרות האחרונות לא חובה. אותו מספר אישור לא יכול להירשם פעמיים באותו יום. בספירת הקופה משווים את הסכום מול סגירת היום של המסופון.

## גרסה 0.5: אשראי אונליין לפי התיעוד המעודכן של נדרים
- **השרת מקים את העסקה בנדרים (CreateTransaction), והסכום ננעל בשרת.** הדפדפן שולח לטופס התשלום רק את מזהה העסקה, ולכן אי אפשר לשנות את הסכום בדפדפן.
- **נדרים שולחים עדכון גם על ניסיון שנכשל.** עדכון כזה לא נרשם כתשלום. ההודעה מנדרים נשמרת על התשלום, והקונה יכול לנסות שוב.
- **עסקה זמנית, בלי מספר אישור,** לא נרשמת כתשלום, ומופיעה בדוחות ב"תשלומים לבדיקה".
- **חתימת HMAC:** בנדרים: הגדרות ← API ← Webhook ← חתימת HMAC. מגרילים מפתח, ושומרים אותו ב-Supabase ← Edge Functions ← Secrets בשם `NEDARIM_WEBHOOK_SECRET`. רק אחרי זה לוחצים "הפעלה" בנדרים. מהרגע שהסוד מוגדר, כל עדכון בלי חתימה תקינה נדחה. בלי הסוד, המערכת בודקת את כתובות ה-IP של נדרים.
- **🧪 מצב בדיקה:** בהגדרות ← תשלום באשראי. הוא משתמש במוסד הבדיקות של נדרים (מוסד 0) ובכרטיסי טסט, למשל 4557430402321333, תוקף 05/31, CVV 098. זה לא מחייב באמת. הוא מחייב מייל ב"פרטי המזנון". את הטעינות והמכירות שנרשמו בבדיקה צריך לבטל ידנית אחרי הבדיקה.
- את הפונקציה `nedarim` צריך **לעדכן ב-Supabase**: מדביקים מחדש את `supabase/functions/nedarim/index.ts` ← Deploy.

## גרסה 0.6: אימות מחיר מוכרים
- **בחירת בחור שמסומן "מוכר",** בסריקת כרטיס או מהרשימה, פותחת חלון **"🔐 אימות מחיר מוכרים"**:
  - המוכר שקונה מקיש **את הקוד האישי שלו**.
  - או: לוחצים **"אישור מנהל"**, ומנהל מקיש את הקוד שלו.
  - בלי אימות, הקנייה נעשית במחיר רגיל.
- **אם המוכר המחובר לקופה קונה לעצמו,** אין צורך בקוד, כי הוא כבר מזוהה.
- **אם מסמנים "מחיר מוכרים" ידנית,** בוחרים מי קונה, ואז נדרש אימות.
- **בארנקים:** לבחור שמסומן "מוכר" מקשרים את **המשתמש שלו בקופה**, כדי שהמערכת תדע איזה קוד לבקש.
- **בדוחות:** טבלה **"🔐 קניות במחיר מוכרים"** עם הקונה, מי אישר, אופן האימות, מי מכר, הסכום והחיסכון.

### טביעת אצבע (בהכנה)
האפליקציה כבר מוכנה לקורא טביעות אצבע שמחובר למחשב הקופה דרך תוכנת גשר מקומית (`http://127.0.0.1:17575`, הפרוטוקול מתועד ב-`src/fp.js`).
כשהגשר רץ, מופיעים אוטומטית: **👆 כניסה באצבע** במסך הכניסה, **👆 אימות באצבע** באימות מחיר מוכרים, ו**רישום אצבע** בעריכת מוכר בהגדרות.
כל עוד אין גשר, שום דבר מזה לא מוצג, והכל עובד עם קודים.
